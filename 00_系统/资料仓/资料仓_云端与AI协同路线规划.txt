资料仓｜云端与 AI 协同路线规划
版本：v1.0
日期：2026-09-13
状态：规划存档

一、总体定位
GitHub 仓库作为长期“资料仓”与结构/版本档案库。
目标不是把所有文件都塞进 GitHub，而是让不同类型资料进入最合适的存储层，并最终由 AI 客户端统一调用。

二、核心分层
1. GitHub：知识、结构、文本、版本
- 正文 TXT/MD
- 角色设定
- 世界设定
- 研究资料
- JSON/CSV 等结构化数据
- 变动记录
- 项目代码与配置
- Git 历史作为真实版本档案

2. 云端素材仓：大体积媒体
优先考虑 Google Drive，后续可扩展其他云存储。
用于：
- 世界地图
- 区域地图
- 地点/场景图
- 角色形象
- 角色动作/表情素材
- 音频示例
- 配音参考音频
- 视频与原始素材

3. ChatGPT Library：AI 工作台
用于高频、当前正在处理的资料，以及需要在 ChatGPT 中直接读取的文件。
不作为长期大型媒体总仓。

三、核心文件管理规则
长期变动的文字资料原则上只保留：
- 当前文件
- 变动记录文件
- Git 历史

例如：
第一章_开门.txt
第一章_开门_变动记录.txt

正文文件永远代表当前版本。
变动记录记录：
- 版本号
- 日期
- 修改位置
- 修改内容
- 修改原因
- 是否影响设定/世界观/后续剧情

Git 历史负责保存真实旧版本，因此不需要为每次修改复制一份正文。

四、角色与世界设定分类
角色设定与世界设定分开建立目录。

示例：
角色设定/
└── 王度/
    ├── 王度_当前设定.txt
    ├── 王度_设定变动记录.txt
    └── 蓝星往事/
        ├── 王度_蓝星往事.txt
        └── 王度_蓝星往事_变动记录.txt

世界设定/
├── 世界观/
├── 地理/
├── 历史/
├── 能力体系/
└── 社会结构/

五、角色数字资产
角色未来形成“文字人格 + 视觉 + 声音 + 视频”的完整数字资产。

建议结构：
角色资产/
└── 王度/
    ├── 形象/
    ├── 声音/
    ├── 配音参考/
    └── 视频参考/

声音资料除音频文件外，还应有声音设定/配音说明 TXT，用于描述：
- 声线
- 语速
- 音量
- 呼吸
- 停顿
- 情绪表达
- 不同场景下的演绎方式

六、容量策略
TXT、MD、JSON、CSV 等小型资料直接放 GitHub。
小型图片/音频可直接放 GitHub。
大型图片、音频、视频不作为普通 Git 文件长期保存。
需要时使用 Git LFS 或独立云存储。
视频和大量原始媒体优先放独立素材仓，避免 Git 历史持续膨胀。

七、未来 AI 客户端方向
最终建立统一资料层，由 AI 客户端负责调用不同存储：

AI
├── GitHub Storage
│   └── 设定/正文/规则/历史/结构化资料
├── Cloud Storage
│   └── 图片/地图/音频/视频
└── AI Workspace
    └── 当前任务/临时资料/高频文件

未来可扩展：
- GitHub
- Google Drive
- OneDrive
- Dropbox
- S3
- 阿里云 OSS
- 腾讯云 COS
- 其他兼容对象存储

通过统一 Storage 接口，使以后更换云平台不需要重写 AI 核心逻辑。

八、当前路线
阶段 1：先稳定 GitHub 资料仓目录与版本规则。
阶段 2：建立云端素材仓，优先评估 Google Drive。
阶段 3：建立 GitHub 与云端素材之间的引用/索引规则。
阶段 4：角色逐步建立形象、声音、配音参考等数字资产。
阶段 5：开发自己的 AI 客户端/编排层，统一访问 GitHub 与云端资料。
阶段 6：进一步接入地图、角色状态、关系、事件、媒体资产，逐步向“世界引擎”资料底座演化。

九、基本原则
- GitHub 不追求“什么都存”，而追求结构清晰、版本可靠。
- 大型媒体不污染 Git 历史。
- 当前版本与历史版本分离管理。
- AI 可读性优先。
- 文件目录承担结构，变动记录承担解释，Git 历史承担真实版本。
- 未来允许更换云存储，不让资料体系绑定单一平台。
